Intelligent Document Processing Platform

Klearnow
Problem

Document processing relied on rule-based and ML models with heavy manual intervention from operations. As shipment volume grew, scaling meant adding more operational staff — a bottleneck for growth.

What I built
  • Ingests email attachments from customer mailboxes and converts PDFs, spreadsheets, EML files, and other formats into images.
  • Performs OCR and document classification, then routes each document to document-specific LLM prompts for structured extraction.
  • Validates and sanitizes extracted data before persisting it to SQL databases.
  • Integrated the LLM-based extraction pipeline while preserving compatible parts of the existing ML-based workflow, enabling a gradual migration.
Impact
  • Processes approximately 500 shipments/day.
  • Document conversion service handles roughly 30,000 document images/day across PDFs, spreadsheets, EML files, and other formats.
  • Achieved approximately 80% automated extraction accuracy, cutting manual review effort and letting operations scale without proportional headcount growth.
  • Supports both fully automated and semi-automated workflows, where operations review AI-extracted data when required before customs brokers receive the final shipment information.

Java gRPC Routing Layer

Klearnow
Problem

The existing reverse proxy handled UI requests asynchronously — publishing events to Kafka and waiting for a response — so the request stayed open and could time out even when backend processing succeeded. Some interactions needed synchronous, lower-latency responses.

What I built
  • Designed and implemented a configurable gRPC routing layer inside the Java reverse proxy.
  • Allowed selected request types to bypass the async Kafka workflow and talk directly to backend services via gRPC.
  • Introduced configuration-driven routing so only latency-sensitive operations used synchronous communication.
  • Implemented semaphore-based concurrency control to prevent thread pool exhaustion under load.
Impact
  • Reduced response latency for synchronous, latency-sensitive workflows.
  • Prevented thread pool exhaustion under concurrent load.
  • Enabled a gradual migration without disrupting the existing Kafka-based architecture.

Memory Optimization — Document Converter

Klearnow
Problem

The document conversion service hit OutOfMemory errors on large files — memory usage occasionally grew to nearly 10 GB, causing pod instability and crashes. Running on Java 8, garbage collection alone couldn't reliably recover memory under peak load.

What I built
  • Added runtime memory monitoring that pauses new document processing when JVM memory approaches 95% of the container limit, giving GC room to recover before continuing.
  • Built an alerting mechanism that automatically identifies the specific files responsible for abnormal memory growth, making production debugging significantly easier.
Impact
  • Eliminated repeated pod crashes caused by oversized documents.
  • Improved production stability of the conversion service.
  • Enabled faster identification and resolution of problematic customer files.

Auto ISF Filing

Klearnow
Problem

Importer Security Filing (ISF) submissions are mandatory before cargo reaches the U.S. Missing or invalid filings risk penalties starting at $5,000/shipment, while manual review slowed processing and added operational effort.

What I built
  • Designed and implemented a rule-based SOP engine that retrieves customer-specific SOP profiles from MongoDB.
  • Automatically populates missing shipment fields and applies configurable validation rules.
  • Submits validated filings directly to CBP.
Impact
  • Automatically files 100–150 shipments/day.
  • Reduced manual intervention for ISF submissions.
  • Achieved near-zero missed ISF filings, helping avoid costly compliance penalties.
